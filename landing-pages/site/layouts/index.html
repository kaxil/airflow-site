From nightly batch to AI agents

One scheduler, one UI and one run history for every kind of workflow your teams run.

Data pipelines

Schedule on time, on data, or both

Run a pipeline on a cron schedule, when the assets it reads are updated, or on a mix of the two. Retries, backfills and a history of every run come with the scheduler.

  • When one team's Dag updates an asset, the Dags that read it start
  • Backfill any date range from the UI, the REST API or the CLI
  • With a Git Dag bundle, each run keeps one version of the code, and the UI shows it
Asset-aware scheduling {{ $arrow }}

AI and agents

Run LLM calls and agents as tasks

The Common AI provider turns a model call or a tool-using agent into an ordinary task, with connections, retries, logs and run history like any other. Human-in-the-loop operators hold a task until a person decides.

  • @task.llm returns output validated against a Pydantic model
  • @task.agent gives an agent toolsets; with durable=True, a retry replays the model and tool calls that already finished instead of running them again
  • ApprovalOperator waits for a person to approve or reject in the UI

Event-driven

Start a run when an event arrives

An asset watcher listens to a message queue from the triggerer and starts a Dag run when a message arrives. No sensor holds a worker slot while it waits.

  • MessageQueueTrigger reads from Apache Kafka, Amazon SQS, Redis and more
  • Deferrable operators wait in the triggerer too, so waiting costs no worker slot
  • Since 3.4, a Dag scheduled on one asset starts a run for each event by default

Any language

Write Dags and tasks in Go, Java or TypeScript

Since Airflow 3, tasks talk to Airflow through the Task Execution API instead of its database. That made Task SDKs in other languages possible, and in 3.4 a whole Dag can be defined in one.

  • Go, Java and TypeScript SDKs, experimental in 3.4
  • A Python Dag can hand single tasks to another language
  • Dags in YAML, validated against a schema, also experimental

Operations

Know when a run is late, not only when it fails

A deadline alert, still experimental, calls you when a run hasn't finished in time. The audit log records who triggered, cleared or paused what.

  • Deadlines count from when a run was queued, its logical date, a fixed time or its average runtime
  • Pause a Dag gracefully, letting its active runs finish first
  • Multi-team deployments, experimental: each team gets its own Dag bundles, connections and executors

Write Dags in plain Python

A Dag is a Python function, and each task is a function inside it. Return values pass between tasks, and an asset links one Dag to the Dags that read its output.

  1. 01
    Tasks are functions

    @task turns a function into a task with retries, logs and a history of every run.

  2. 02
    Schedule on time or on data

    ingest_orders runs daily. Its load task updates the orders asset, which starts orders_report.

  3. 03
    Test it on your laptop

    airflow dags test runs a Dag in one process, with no scheduler or workers.

Questions

Upgrading from Airflow 2

Is Airflow 2 still supported?

No. Airflow 2 reached end of life on 22 April 2026 and gets no more fixes, security fixes included. See supported versions.

Do I have to rewrite my Dags?

Often only the imports change. Ruff's AIR301 and AIR302 rules flag breaking changes, such as operators that moved to provider packages, and ruff check dags/ --select AIR301,AIR302 --fix fixes many of them. AIR311 and AIR312 flag recommended updates, such as importing dag and task from airflow.sdk. The upgrade guide covers the rest.

What changed in Airflow 3?

A new React UI, the Task Execution API that lets tasks run anywhere, Dag versioning, backfills run by the scheduler, and event-driven scheduling with assets. The release notes list every change since.

Running Airflow

Which Python versions are supported?

Airflow {{ $release.short }} supports Python {{ $release.python }}. Run it on Linux in production; macOS, and Windows through WSL2, are fine for development.

How do I run it in production?

With the official Docker image, the Helm chart for Kubernetes, or a pip install pinned with a constraints file. See production deployment.

Is it free?

Yes. Apache Airflow is free and open source under the Apache License 2.0. If you'd rather not run it yourself, several companies offer managed services; see the ecosystem page.

What's inside

An API server, a scheduler, a Dag processor and a triggerer around one metadata database. Workers run tasks wherever they fit and report back through the Task Execution API.

  • Workers need no database access

    Task code on workers talks to Airflow through the Task Execution API, so workers can run without credentials for the metadata database.

  • A version for every run

    With a versioned Dag bundle such as Git, a run uses one version of the code from start to finish, and the UI shows that version's code and graph.

  • Waiting costs no worker slot

    Deferred tasks and asset watchers wait in the triggerer.

  • Several executors at once

    Send each task to the executor that suits it, in one deployment, or write your own.

  • Built to extend

    Provider packages, plugins with React views, custom executors and auth managers.
